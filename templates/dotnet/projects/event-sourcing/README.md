# SampleApp

.NET API with event sourcing, Clean Architecture, DDD and CQRS, generated by `romanctl`.

```bash
romanctl run sample-app
dotnet test
```

Address: http://localhost:5082. OpenAPI document: `/openapi/v1.json`.

## Layers

Dependencies always point inward. A test in `ArchitectureTests` enforces it.

| Project | Contents | Depends on |
|---|---|---|
| `SampleApp.Domain` | Aggregates, events and business rules | nothing |
| `SampleApp.Application` | Commands, queries, projections and the `IEventStore` and `IReadModelStore` ports | Domain |
| `SampleApp.Infrastructure` | Event store and read models | Application |
| `SampleApp.Api` | HTTP endpoints | Application, Infrastructure |

## Event sourcing

The state of an order is the sequence of its events: `OrderCreated`, `ItemAdded` and `OrderPlaced`. The aggregate
decides by raising events and rebuilds itself by applying each one in `When`. Saving appends the new events to the
stream, checking the version that was read: if another operation saved first, the API answers 409.

Queries do not rebuild the aggregate. They read `OrderSummary`, a read model that `OrderSummaryProjection` updates
on every saved event. `GET /orders/{id}/events` shows the stream.

| Method | Path | |
|---|---|---|
| `POST` | `/orders` | creates an order |
| `POST` | `/orders/{id}/items` | adds an item |
| `POST` | `/orders/{id}/place` | places the order |
| `GET` | `/orders/{id}` | the order summary |
| `GET` | `/orders?limit=50` | the most recent orders |
| `GET` | `/orders/{id}/events` | the order events |

## Persistence

PostgreSQL with [Marten](https://martendb.io): events go to the Marten event store, and projections run in the
same transaction. Tables are created on the first write. Run `romanctl start postgres` before starting the API.

The tests in `Postgres/` run against the database when `ConnectionStrings__Default` is set and are skipped without it.
The HTTP tests use the in-memory event store.
