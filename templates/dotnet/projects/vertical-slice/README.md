# SampleApp

.NET API with Vertical Slice Architecture and Minimal APIs, generated by `romanctl`.

```bash
romanctl run sample-app
dotnet test
```

Address: http://localhost:5081. OpenAPI document: `/openapi/v1.json`.

## Slices

Each use case is one file in `Features/<Feature>/`, with everything it needs: the request and response
records, the body validation, the handler and the endpoint mapping (`MapEndpoint`). There is no
mediator and no shared service layer. A slice does not use another; a test in `ArchitectureTests` ensures that.

| Folder | Contents |
|---|---|
| `Features/Orders` | `CreateOrder`, `AddItem`, `PlaceOrder`, `GetOrder` and `ListOrders` |
| `Domain` | The `Order` aggregate, the `Money` value object and the business rules |
| `Data` | `AppDbContext` and the EF Core mapping |
| `Endpoints.cs` | The list of registered slices |

The rules live in the domain; the slices only orchestrate. An invalid body returns 400, a violated rule returns 422 and
an unknown resource returns 404, always as ProblemDetails.

## Persistence

PostgreSQL with EF Core. Run `romanctl start postgres` before starting the API.
In development, the `sample_app` database is created on startup with `EnsureCreated`, which is not
meant to evolve the schema: adopt EF Core migrations before you have data that matters.

The slice tests use the EF Core in-memory provider. The test against PostgreSQL only runs with the
`ConnectionStrings__Default` variable set.
