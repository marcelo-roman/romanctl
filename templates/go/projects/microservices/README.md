# SampleApp

Two Go microservices, orders (`orders`) and billing (`billing`), generated by `romanctl`. Each one starts on its own and
can be published on its own; they only talk through integration events.

```bash
romanctl run sample-app        # starts both, with [orders] and [billing] at the start of each log line
go test ./...
```

| Service | Address | Program |
|---|---|---|
| `orders` | http://localhost:8091 | `go run ./cmd/orders` |
| `billing` | http://localhost:8092 | `go run ./cmd/billing` |

Each one's port changes with the `PORT` variable in that process's environment, as in `docker-compose.yml`. Do not put
it in `.env`: it applies to both processes, and they would fight over the same port.

## Structure

| Folder | Contents |
|---|---|
| `cmd/orders`, `cmd/billing` | Wires one service's adapters and starts the server |
| `internal/services/orders` | Orders: `domain`, `application` and `adapters` (HTTP, memory, PostgreSQL) |
| `internal/services/billing` | Billing: `domain`, `application` and `adapters` |
| `internal/platform` | The little both share: the event envelope, the outbox relay, the transports and the HTTP helpers |
| `internal/e2e` | The whole flow in a single process: order, outbox, relay, in-memory broker and invoice |

A service never imports the other, the domain does not import adapters and the platform does not know the services. The
test in `internal/architecture` enforces all three rules. The contract between them is the event JSON: billing reads only
the fields it needs.

## Flow

1. `POST /orders/{id}/place` places the order and writes the `orders.order-placed` event to the outbox, in the same
   transaction as the order.
2. The outbox relay, inside `orders`, publishes the pending events and only marks them as sent after the transport
   confirms. If it fails, it retries with growing backoff: delivery is at least once.
3. `billing` receives the event and issues the invoice. The event id is recorded in the same operation that writes the
   invoice, so a repeated event does not create another one.

## Endpoints

| Service | Method | Path | What it does |
|---|---|---|---|
| orders | `POST` | `/orders` | Creates an order: `{"customerName": "Ana"}` |
| orders | `POST` | `/orders/{id}/items` | Adds an item: `{"productName": "Pen", "quantity": 2, "unitPrice": 3.5}` |
| orders | `POST` | `/orders/{id}/place` | Places the order |
| orders | `GET` | `/orders/{id}` | One order |
| orders | `GET` | `/orders?limit=50` | The most recent orders |
| billing | `GET` | `/invoices/{orderId}` | The invoice of an order |
| billing | `GET` | `/invoices?limit=50` | The most recent invoices |
| both | `GET` | `/health` | Service health |

Invalid JSON answers 400, a business rule violation 422 and what does not exist 404, always as `application/problem+json`.
