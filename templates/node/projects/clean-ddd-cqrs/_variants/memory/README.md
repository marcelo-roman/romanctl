# SampleApp

Node API with NestJS, Clean Architecture, DDD and CQRS, in TypeScript, generated by `romanctl`.

```bash
romanctl run sample-app
npm test
```

Address: http://localhost:3000. The `PORT` variable changes the port.

| Script | What it does |
|---|---|
| `npm start` | Compiles to `dist/` and starts the API, reading `.env` if it exists |
| `npm test` | Type-checks and runs the tests with Vitest |
| `npm run build` | Only compiles |

## Layers

Dependencies always point inward. The test in `test/architecture.test.ts` enforces it.

| Folder | Contents | Depends on |
|---|---|---|
| `src/domain` | Aggregates, value objects, events and business rules | nothing, not even packages |
| `src/application` | Commands, queries, handlers and the ports they need (`OrderReadStore`, `Clock`) | domain, `@nestjs/cqrs` |
| `src/infrastructure` | Persistence and clock | application, domain |
| `src/api` | Controllers, error handling and the module that wires everything | all |

## CQRS

Controllers only build the message and send it through the `CommandBus` or the `QueryBus` of `@nestjs/cqrs`. Commands
change state through the aggregate repository; queries read through the `OrderReadStore` and return views. The events
the aggregate raises, such as `OrderPlaced`, go out through the `EventBus` after being saved.

## Endpoints

| Method | Path | What it does |
|---|---|---|
| `POST` | `/orders` | Creates an order: `{"customerName": "Ana"}` |
| `POST` | `/orders/{id}/items` | Adds an item: `{"productName": "Pen", "quantity": 2, "unitPrice": 3.5}` |
| `POST` | `/orders/{id}/place` | Places the order |
| `GET` | `/orders/{id}` | One order |
| `GET` | `/orders?limit=50` | The most recent orders |
| `GET` | `/health` | API health |

Violated business rules answer 422, orders that do not exist, 404, and invalid bodies, 400, always as
`application/problem+json`.

## Persistence

In memory: the data is gone when the API stops. To use PostgreSQL, generate the project with `--with postgres`.
