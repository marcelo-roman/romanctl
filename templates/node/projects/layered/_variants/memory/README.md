# SampleApp

Lean layered Node API, with Fastify and TypeScript, generated by `romanctl`.

```bash
romanctl run sample-app
npm test
```

Address: http://localhost:3001. The `PORT` variable changes the port.

| Script | What it does |
|---|---|
| `npm start` | Compiles to `dist/` and starts the API, reading `.env` if it exists |
| `npm test` | Type-checks and runs the tests with Vitest |
| `npm run build` | Only compiles |

## Layers

A classic layered architecture, with no aggregates and no CQRS: each request goes down from routes to services and
from services to repositories. The test in `test/layering.test.ts` enforces the direction.

| Folder | Contents | Depends on |
|---|---|---|
| `src/models` | The data types, such as `Task` | nothing |
| `src/repositories` | The repository interfaces and the implementation in `memory/` | models |
| `src/services` | The business rules | models and the repository interfaces, only with `import type` |
| `src/routes` | Fastify routes, JSON schemas and the translation of errors into problem JSON | services, models |
| `src/app.ts` | `buildApp`, which wires the routes over the repositories it receives; the tests use it with the in-memory ones | all |
| `src/server.ts` | Picks the repositories and starts the server | all |

Routes only validate the shape with the Fastify schemas and call the service. Every rule lives in the service.

## Endpoints

| Method | Path | What it does |
|---|---|---|
| `POST` | `/tasks` | Creates a task: `{"title": "Buy bread", "dueDate": "2026-12-31"}` |
| `GET` | `/tasks?done=false&limit=50` | The most recent tasks; `limit` is 50 when omitted and at most 200 |
| `GET` | `/tasks/{id}` | One task |
| `PATCH` | `/tasks/{id}` | Changes `title`, `done` or `dueDate` (`null` clears the date) |
| `DELETE` | `/tasks/{id}` | Removes the task |
| `GET` | `/health` | API health |

## Rules

- The title is required, is trimmed and has at most 200 characters.
- On creation, `dueDate` cannot be in the past; the comparison uses today's date in UTC.
- Completing a task that is already done answers 409: the client learns the change did not happen.

Errors go out as `application/problem+json`, in the `{"status", "title", "detail"}` shape: invalid body or parameter,
400; task that does not exist, 404; task already done, 409; violated business rule, 422.

## Persistence

In memory: the data is gone when the API stops. To use PostgreSQL, generate the project with `--with postgres`.
