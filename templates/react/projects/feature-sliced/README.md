# Sample App

React front-end for the orders API, organized with Feature-Sliced Design, generated by `romanctl`.

```bash
romanctl run sample-app
npm test
```

Address: http://localhost:5173.

| Script | What it does |
|---|---|
| `npm run dev` | Starts Vite on port 5173, with the proxy to the API |
| `npm test` | Checks the types, runs ESLint with the layer rules and the tests with Vitest |
| `npm run build` | Checks the types and builds `dist/` |
| `npm run lint` | ESLint only |

## The API

The front-end talks to the orders API that every `romanctl` back-end template exposes, with the same contract:

| Method | Path | What it does |
|---|---|---|
| `POST` | `/orders` | Creates an order: `{"customerName": "Ana"}` → `201 {"id": "..."}` |
| `POST` | `/orders/{id}/items` | Adds an item: `{"productName": "Pen", "quantity": 2, "unitPrice": 3.5, "currency": "USD"}` → `204` |
| `POST` | `/orders/{id}/place` | Places the order → `204` |
| `GET` | `/orders/{id}` | One order, with items, total and currency |
| `GET` | `/orders?limit=50` | The most recent orders |

Errors arrive as problem JSON (`{"status", "title", "detail"}`) with 400, 404 or 422, and the screen shows the `detail`.

### Where it points

In development, the browser calls `/api/...` on Vite itself, and Vite forwards it to `VITE_API_URL` without the
`/api` prefix. That way the API does not need to allow CORS. Without `VITE_API_URL`, the target is
`http://localhost:8090`, the port of the Go template. For another back-end, create a `.env` from `.env.example`:

| Back-end | `VITE_API_URL` |
|---|---|
| Go hexagonal and DDD | `http://localhost:8090` |
| .NET Clean, DDD and CQRS | `http://localhost:5080` |
| .NET event sourcing | `http://localhost:5082` |
| .NET modular monolith | `http://localhost:5083` |
| Node Clean, DDD and CQRS | `http://localhost:3000` |
| Python hexagonal and DDD | `http://localhost:8000` |
| Java hexagonal and DDD | `http://localhost:8080` |
| Kotlin hexagonal and DDD | `http://localhost:8081` |
| PHP hexagonal and DDD | `http://localhost:8002` |
| Rust hexagonal and DDD | `http://localhost:3100` |

Check the port in the back-end's `romanctl.yaml`. With `VITE_API_PROXY=false`, the browser calls `VITE_API_URL`
directly, and then the API must answer with CORS.

```bash
romanctl new orders-api --stack go --arch hexagonal,ddd
romanctl up orders-api -d
romanctl up sample-app -d
```

## Layers

Each layer only imports from the layers below it, and from another slice only through its `index.ts`, the slice's
public API. Two slices of the same layer do not import each other. ESLint, with `eslint-plugin-boundaries`, enforces
the three rules and runs in `npm test`.

| Layer | Contents | May import |
|---|---|---|
| `src/app` | Entry point, providers (TanStack Query), routes, layout and styles | all |
| `src/pages` | `orders-list`, `order-details` and `not-found` | widgets, features, entities, shared |
| `src/widgets` | `orders-table` and `order-summary`, ready-made screen blocks | features, entities, shared |
| `src/features` | `create-order`, `add-order-item` and `place-order`, each with `ui`, `model` and `api` | entities, shared |
| `src/entities` | `order`: types, contract mapping, money formatting, queries | shared |
| `src/shared` | HTTP client with the problem JSON error, configuration, utilities and the UI kit | shared |

Components only render. Formatting, form conversion and rules live in `model` and `lib`, tested without React.

## Tests

Tests live next to the code, in `*.test.ts(x)`. MSW intercepts the calls and answers like the real API, with an
in-memory back-end in `tests/support/orders-api.ts`. `tests/support` also has `renderRoutes`, which sets up TanStack
Query and an in-memory router.

## Adding to the project

```bash
romanctl add entity Customer        # src/entities/customer: model, API, queries and tests
romanctl add feature archive-order  # src/features/archive-order: form with ui, model, api and test
romanctl add page Customers         # src/pages/customers, with the route and the menu link
```
